AI 投标技术方案生成工作台

一次 toB 投标交付的产出结构与样例片段 ｜ 2026.08 ｜ 独立设计与实现
脱敏说明：本页展示该工作台在一次真实投标交付中产出的物料结构与方法论， 客户名称与商业信息已做脱敏处理，仅保留格式、结构与工作流设计。

一、这个产品做什么

面向 toB 投标场景：把"读招标文件 → 写技术方案 → 产出配套物料"这条链路做成一个工作台。

上传招标文件→ 解析评分项→ 生成方案框架→ 分章节撰写正文→ 输出飞书文档

技术栈：React 18 + Vite + 工作流编排；支持 PDF / DOC / DOCX / XLS / XLSX 上传（≤50MB）， 支持拖拽上传、提交前摘要确认、实时进度、失败原因区分与修改重试。

二、核心流程完成度自检 10 / 10

  1. 创建投标项目（项目列表 → 新建）
  2. 填写项目信息（名称、招标单位、截标时间、负责人、备注）
  3. 上传招标文件（点击上传 / 拖拽上传 / 删除 / 重新上传）
  4. 填写撰写要求（默认模板 + 6 个快捷要求标签）
  5. 提交前摘要确认（显示完整信息供核对）
  6. 启动 AI 生成（连接工作流）
  7. 实时显示生成状态与运行时长
  8. 成功 / 失败状态区分（成功给文档链接，失败给具体原因）
  9. 打开文档 / 复制链接
  10. 失败后修改信息重新生成

另含防重复提交、未配置密钥时可用的演示模式、AI 生成内容的人工审核提醒。

三、一次交付的完整产出清单 12 项

投标主件

  1. 招标文件专用公司简介
  2. 服务承诺书
  3. 技术方案正文（AI 生成初稿 → 人工补充资质与案例）

品牌与营销物料

  1. 全套营销材料
  2. 全场景文案优化方案（售前 / 客服 / 售后 / 朋友圈等场景分列）
  3. 宣传词优化方案
  4. 公司介绍文案（修正版）

视频物料

  1. 口播脚本（提词器专用版，含停顿点与动作提示）
  2. 拍摄指导手册（提词器 App 推荐、设备清单、场景布置、1 小时拍摄流程）
  3. 剪辑教程（剪映）
  4. 视频封面设计方案（3 套方案，含布局稿与制作步骤）
  5. 发布文案与话题标签（小红书 / 抖音分平台方案）

这份清单本身就是产品判断：AI 的价值不只在于"把方案正文写出来"， 而在于把"投标准备"当成一条完整工作流来拆解——从资质文件一直做到发布物料。

四、样例片段

样例 1：口播脚本（提词器格式）

提词器脚本的关键不是文字，而是可念性——停顿位置、动作提示、重音标记。
【使用说明】
- "/" 表示停顿换气点
- "（）" 内是动作提示，不要念出来
- 加粗文字是重点，要强调

我还在办公室赶标书 /
旁边同事 / 已经通宵第三天了

（表情：疲惫，摇头）

评分项 / 藏得到处都是 /

（停顿）

AI 会自动帮你 / 提取所有评分项 /
生成完整的技术方案框架 /

（手势：数手指配合）

记住 /

最终还是要人工审核的 /
咱们是提升效率 / 不是偷懒

（表情：认真）

样例 3：拍摄指导手册（设备与场景清单）

准备阶段（15 分钟）

设备检查
  ✅ 手机充满电（或连接充电器）
  ✅ 清理手机镜头
  ✅ 安装提词器 App
  ✅ 准备手机支架 / 三脚架
  ✅ 准备补光灯（或台灯）
  ✅ 准备领夹麦克风（如果有）

场景布置
  位置：靠窗位置（自然光充足），避免逆光
  背景：书架（最佳，显专业）

提词器设置
  字号：调到最大，能在 1.5 米外看清
  滚动速度：匹配语速，多试几次
  背景：黑底白字，减少反光

五、从这次交付里沉淀的方法

① 交付物要成套，不要单件

客户要的不是"一份文案"，而是"这套物料能不能直接用"。 所以脚本、拍摄、剪辑、封面、发布文案要一起给。

② 给执行者留操作空间

提词器脚本标注停顿与动作，封面方案给 ASCII 布局稿—— 让不懂设计的人也能照着做出来，物料才真的会被用。

③ 明确 AI 的边界

脚本里写死一句「AI 生成的是初稿，最终还是要人工审核」。 这不是免责，是把预期管理前置，反而更容易被采纳。

④ 把流程本身当产品

从招标文件到发布物料是一条链。 拆清楚每一环的输入输出，才能判断哪一环该交给 AI。
