行业分析工作台

把「行业研究」这件事，从"问模型要答案"改造成"可验证的结构化调研流程"。
要解决的问题
大模型做行业分析时最大的风险不是答不出，而是编得像真的——编造文件名、编造数字、用"较强/较弱"这类无法判定的表述填满版面。
核心机制一：证据分级
每个事实字段强制标注 A（公开可查，须给到文件名+年份）/ B（推断，须写出推断链）/ C（纯推测）。C 档一律不进正文，只进结尾「待验证清单」；查不到就写「未获取」，不许用推测填满。
核心机制二：对抗式校验
Step 5 让模型切换角色，扮演该行业 12 年从业者，专攻报告里 B/C 档和「未获取」的字段，并指出哪句话暴露了外行。
核心机制三：反讨好立场
系统提示词结尾：「你不需要让用户满意。你需要让用户知道哪些是真的、哪些是你编的。」
怎么试最快：点「看演示」——会播放一份预置的示例输出（标注为演示数据，未调用模型），用于快速查看输出结构与证据分级机制。
想真实运行：点右侧按钮填入你自己的 DeepSeek API Key（默认协议已配好 OpenAI 兼容）。Key 只存在你本地浏览器，不经过任何服务器。
说明：本页为静态托管页面，真实调用由浏览器直连模型服务商完成。
📱 把「行业分析工作台」加到主屏幕，像 App 一样使用（离线也能看演示）
API 配置
Anthropic 官方 API 对部分地区返回 403「Request not allowed」且不带 CORS 头，浏览器直连必然失败； DeepSeek 等 OpenAI 兼容接口支持浏览器直连，双击本地打开即可用。
自动清理尾部斜杠，再按协议拼接 /v1/chat/completions 或 /v1/messages
仅存储在本地浏览器（localStorage），不会上传到任何服务器
OpenAI 协议填 deepseek-chat；Anthropic 协议填 claude-* 或中转平台的前缀格式
OpenAI 协议固定使用 Authorization: Bearer
仅当接口不带 CORS 头、浏览器直连被拦时才需要。填了就先跑 node proxy-server.js
开启后 A 档证据会先检索核实，但多数三方平台不支持该工具
