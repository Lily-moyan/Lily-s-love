# 情感策略卡

AI 接待 + 真人盖章的一页式关系决策支持。客户口述困扰 → AI 追问 3–5 轮 → 生成策略卡 → 你亲手改关键两句 + 写「我的判断」→ 发链接。

**没有登录、没有支付集成、没有后台工单。** 只有一条闭环，先在今晚把它跑通。

---

## 跑起来

```powershell
cd 情感策略卡
node src/server.mjs
```

打开 http://127.0.0.1:8787

模型 key 不用配：服务端默认从 DSH 凭据库读 `DEEPSEEK_API_KEY`。
正式对外前请换成你自己的 key：

```powershell
$env:DEEPSEEK_API_KEY='sk-你的key'
$env:PORT='8787'
node src/server.mjs
```

自测（会真实调用模型，约 1–2 分钟，花费不到 1 毛）：

```powershell
node tools/e2e.mjs http://127.0.0.1:8787
```

## 一条真实交付长什么样

1. **你**打开首页，把朋友的原话粘进去 → 点开始。
2. **AI** 追问 3–5 轮，一次只问一个，问完自动出卡。
3. 出卡后页面上会多出一条**只有你能看到的**入口：「去批注」。
4. **你**在批注页改两处 —— 「我推荐这一个」的理由、「我的判断」批注 —— 点保存。
5. 回到卡页复制**客户链接**（`/c/<id>`）发给朋友。他打开就是那张卡，可截图、可复制话术。

批注链接（`/admin/<token>`）和客户链接是**同一个页面的两种视图**：客户链接看不到你的编辑面板。
直接把 `chat/<sessionId>` 发给朋友填也行 —— 但那需要你事后手动找卡片，MVP 阶段建议你自己代填。

## 你要改的只有两个文件

这两个是你唯一别人抄不走的东西，代码不用动。

### `knowledge/persona.md` —— 你是谁

决定 AI 的语气、敢不敢下判断、以及客户觉得「这像不像你」。
里面 6 条「核心判断原则」是全卡最值钱的部分，**写成你自己的话**，不要留示例。

### `knowledge/cases.md` —— 案例库

一条案例一段，`---` 分隔。只记四样：阶段、冲突、关键行为、有效打法。
**必须脱敏**：不写姓名、城市、单位、年龄。

> 案例没写够 30 条之前，卡片质量基本取决于 `persona.md`。先写 10 条也能立刻见效。

---

## 卡片在哪儿、怎么进案例库

- 所有会话和卡片都在 `data/app.db`（SQLite，单文件，直接复制就是备份）。
- **入库必须你手动点。** 出卡后 AI 不会自动把任何东西放进案例库；只有你在批注页填了脱敏摘要、点了「确认入库」，这条才会进入以后卡片的参考池。
- 未同意入库的卡片，检索层永远读不到。这一条写在 `src/db.mjs` 的 `archiveContext()` 里。

## 三道安全闸（不要拆）

1. **确定性词表 + 模型分诊双保险**（`src/prompts.mjs` 的 `RISK_PATTERNS` / `triage`）。
   命中家暴、自伤、法律程序、未成年人 → **不生成任何策略**，只输出转介渠道和一句「我不给你招」。
   每一轮客户补充都会重新过一遍，因为风险常常在第三、四轮才说出来。
2. **禁止人格诊断标签**：prompt 里禁，出稿后还有一道安全质检，不合格会返修。
3. **免责声明硬编码**在每张卡底部。

改词表时请只**加**不要减。误报的代价是少做一单，漏报的代价是这个产品不能再做。

## 出稿流程（为什么这么慢还值得）

```
访谈记录
  → 写稿（长 prompt + 你的角色卡 + 案例库）
  → 并发两道质检：安全（标签/承诺/操控手法/事实与推测混淆）
                  有用（标题是不是套话、三个选项是否真的不同、话术能不能直接发）
  → 有问题就带问题清单返修一版
  → 规整结构 → 落库 → 给你批注
```

一次出卡大约 20–40 秒，2–4 次模型调用。质检意见会留在 `card.meta.qaIssues` 里，你可以在批注页看到 AI 自我批评了什么，然后决定要不要采纳。

## 部署到能让朋友点开

现在只能本机访问。要发到微信群，两条路：

**A. 临时公网隧道（今晚就能用）**

```powershell
# 任选其一，装好之后
cloudflared tunnel --url http://127.0.0.1:8787
# 或
npx localtunnel --port 8787
```

拿到公网域名后重启服务，把域名写进环境变量，这样生成的链接才是对的：

```powershell
$env:PUBLIC_BASE_URL='https://你的域名'
node src/server.mjs
```

**B. 正式部署**：任意支持 Node 22+ 的容器/主机，挂一个持久化卷到 `data/`，设 `PUBLIC_BASE_URL`。

> 别把 `data/app.db` 放进公开仓库 —— 里面是客户的原话。

## 配置项（都有默认值）

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `LLM_BASE_URL` | `https://api.deepseek.com` | 任何 OpenAI 兼容端点 |
| `LLM_MODEL` | `deepseek-chat` | 访谈和出稿都用它 |
| `LLM_API_KEY_ENV` | `DEEPSEEK_API_KEY` | key 从哪个环境变量取 |
| `PUBLIC_BASE_URL` | `http://127.0.0.1:8787` | 生成链接用的域名 |
| `CONSULTANT_NAME` | `我` | 批注署名 |
| `DB_PATH` | `data/app.db` | 数据库位置 |

收费口径、交付时效写在 `src/config.mjs` 的 `COPY` 里，改文案不用碰逻辑。

## 两个已踩过的坑（别回退）

**1. 不要使用 `response_format: {type:'json_object'}`。**
实测 DeepSeek 在「长 system prompt + JSON 输出模式」组合下会**确定性地**返回
`finish_reason=stop` 但 `content` 全是空格（30–60 token 全吐空白），重试无法恢复。
现在的做法是 prompt 里写死 JSON 结构、靠 `parseJson` 解析、不合格就追加指令重试，失败再用
`REPAIR_SYSTEM` 把这一轮的人话回复转回 JSON。更稳，而且换供应商不用改。

**2. 不要在对话末尾追加「（系统提示：请按格式输出）」这类假 user 消息。**
它会覆盖 prompt 前部的格式约束，让模型改成直接回人话，整轮解析失败。
轮次信息已经写进 system prompt，不需要额外提醒。
